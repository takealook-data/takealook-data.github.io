**TL;DR**

- 검색 노출을 위해 구글·네이버·Bing 검색 콘솔에 소유확인과 사이트맵 제출을 마쳤습니다.
- 네이버가 Atom 피드를 받지 못해 500 에러가 났고, RSS 2.0 피드를 따로 만들어 해결했습니다. 새 글 URL을 바로 밀어 넣는 IndexNow도 연결했습니다.
- ChatGPT 검색 같은 생성형 AI(GEO)에 노출되려면 Bing 등록과 AI 크롤러 허용 확인이 필요합니다.

글이 몇 편 쌓였는데 정작 검색엔진에는 등록을 안 해둔 상태였습니다. 색인 요청도, 유입 분석도 할 수 없으니 하루를 잡고 한 번에 끝내기로 했습니다. 구글·네이버·Bing 등록부터 IndexNow 연동, 네이버 RSS 오류 수정까지 실제로 진행한 순서대로 정리했습니다.

---

## 1. 소유확인과 사이트맵 제출부터 시작합니다

검색엔진 콘솔에 사이트를 등록하려면 두 가지를 먼저 해야 합니다. 내 사이트라는 걸 증명하는 소유확인, 그리고 크롤러가 읽어갈 sitemap 제출입니다.

1. **구글과 네이버는 메타 태그로 소유권을 증명합니다.** Google Search Console과 네이버 서치어드바이저에서 속성을 추가하면 HTML 확인용 메타 태그를 발급해 줍니다. 구글 것은 Jekyll 테마의 `_config.yml`에 verification 키로 넣었고, 네이버 것은 head 인클루드 파일에 직접 삽입했습니다. 배포하고 1~2분 뒤 콘솔에서 소유 확인을 누르니 승인됐습니다. 한 가지 주의할 점이 있는데, 이 메타 태그를 나중에 지우면 소유권도 같이 사라집니다. 그대로 둬야 합니다.

2. **sitemap 제출은 이미 반쯤 되어 있었습니다.** `jekyll-sitemap` 플러그인을 쓰고 있어서 `sitemap.xml`과 `robots.txt`는 자동으로 생성돼 있었습니다. 구글 콘솔에는 `sitemap.xml` 경로만 입력하면 되고, 네이버에는 전체 URL로 제출했습니다. Bing Webmaster는 더 간단했습니다. Google Search Console 연동 버튼 하나 누르니 사이트와 사이트맵 정보를 그대로 가져왔습니다.

여기까지 하면 크롤러가 정기적으로 방문해서 수집해 갈 수 있는 기본 통로는 열린 셈입니다.

## 2. IndexNow를 붙이고, 네이버 RSS 500 에러를 잡았습니다

사이트맵 제출만으로는 크롤러가 와주기를 기다리는 수밖에 없습니다. 좀 더 빠른 색인을 위해 IndexNow를 붙였고, 그 과정에서 네이버 RSS 제출이 500 에러로 거절되는 문제도 만났습니다.

1. **IndexNow는 새 글 URL을 검색엔진에 직접 밀어 넣는 프로토콜입니다.** sitemap이 크롤러의 방문을 기다리는 방식이라면, IndexNow는 글을 발행하는 시점에 API로 URL을 푸시합니다. 사이트 루트에 소유 증명용 `{key}.txt` 파일을 배포한 뒤, JSON 페이로드를 담은 cURL POST 요청을 보냈습니다. HTTP 202 응답이 오면 접수된 것입니다. 앞으로는 포스트를 발행할 때마다 자동으로 호출되도록 해뒀습니다.

2. **네이버 500 에러의 원인은 Atom 피드였습니다.** `jekyll-feed` 플러그인이 만들어주는 `feed.xml`은 Atom 1.0 규격인데, 네이버 서치어드바이저는 RSS 2.0만 받습니다. 그래서 제출할 때마다 500 에러가 났던 것입니다. Liquid 템플릿으로 `rss.xml`을 따로 만들어 해결했습니다. 블로그, 에세이, 독서, 포트폴리오 컬렉션을 합쳐 최신 20개 글을 RSS 2.0 규격으로 렌더링하도록 했고, 다시 제출하니 정상 접수됐습니다.

기존 Atom 피드는 구글과 일반 RSS 리더용으로 그대로 두고, 네이버용 RSS 2.0을 병행하는 구성으로 정리했습니다.

## 3. 색인 요청까지 넣고, GEO 기반을 점검했습니다

배포를 마치고 색인 요청을 넣는 과정에서 일시적인 오류를 하나 만났습니다. 생성형 AI 검색(GEO) 쪽 준비 상태도 함께 점검했습니다.

1. **URL 검사에서 404가 나와도 사이트가 정상이면 재시도로 풀리기도 합니다.** Google Search Console에서 색인 생성을 요청하는데 실시간 테스트가 "404 찾을 수 없음"을 반환했습니다. 실제 경로와 배포 상태는 정상이었습니다. 몇 분 뒤 같은 URL로 다시 시도하니 통과했습니다. 배포 직후에 이전 버전 HTML이 응답된다면 GitHub Pages CDN 캐시일 수 있으니, URL 뒤에 쿼리 스트링을 붙여 캐시를 우회해서 확인해보는 방법도 있습니다.

2. **GEO와 직접 연결되는 건 Bing 등록, IndexNow, robots.txt입니다.** ChatGPT 검색 같은 생성형 AI 검색은 Bing 인덱스를 소스로 쓰는 경우가 많습니다. 그래서 Bing에 사이트가 수집되도록 해두는 것 자체가 GEO 준비가 됩니다. 여기에 IndexNow로 새 글이 빠르게 전파되게 하고, `robots.txt`에 AI 크롤러를 막는 규칙이 없다는 것까지 확인했습니다. 검색엔진과 LLM이 둘 다 들어올 수 있는 상태입니다.

거창한 작업은 아니었습니다. 다만 이 중 하나라도 막혀 있으면 노출 자체가 안 되니, 한 번은 짚고 넘어갈 필요가 있었습니다.

## 상세 체크리스트 파일을 나눠드립니다

전체 작업을 요약하면 이렇습니다. GitHub Pages + Jekyll 기준이지만, 정적 블로그라면 대부분 그대로 적용됩니다.

- [ ] Google Search Console 소유확인 + sitemap 제출 (메타 태그는 확인 후에도 지우지 않기)
- [ ] Bing Webmaster — Google Search Console 연동으로 가져오기
- [ ] 네이버 서치어드바이저 소유확인 + sitemap 제출
- [ ] 네이버용 RSS 2.0 피드(`rss.xml`) 생성·제출 — Atom 피드는 500 에러
- [ ] IndexNow 키 배포 + 새 글 URL 푸시 → HTTP 202 확인
- [ ] 주요 URL 색인 요청 + `robots.txt`에 AI 크롤러 차단 규칙 없는지 확인

이걸 실제로 따라 하다 보면 "그래서 그 버튼이 어디 있는데?"에서 막히기 쉽습니다. 그래서 각 단계의 클릭 경로, 붙여 넣을 코드, IndexNow cURL 요청 예시까지 담은 md 파일을 따로 만들어뒀습니다. 콘솔 어느 메뉴에서 무엇을 선택해야 하는지, 소유확인 값을 `_config.yml` 어디에 넣는지 수준까지 적혀 있습니다.

이 파일의 용도는 두 가지입니다. 하나는 사람이 보면서 하나씩 체크하는 것이고, 다른 하나는 Claude Code에게 파일을 통째로 주고 "이 체크리스트대로 진행해줘"라고 시키는 것입니다. 메타 태그 삽입, `rss.xml` 템플릿 작성, IndexNow 요청 같은 코드 작업은 알아서 처리해 주고, 사람은 콘솔에서 로그인하고 버튼 누르는 것만 하면 됩니다. 실제로 제가 이 글의 작업을 그렇게 진행했습니다.

## 내 생각

코드 작업은 대부분 Claude Code와 함께 했습니다. 메타 태그 삽입, `rss.xml` 템플릿 작성, IndexNow cURL 요청까지, 콘솔에서 클릭하는 시간을 빼면 크게 어렵지 않았습니다.

특히 네이버 500 에러가 기억에 남습니다. 에러 메시지만 봐서는 원인을 알 수 없었는데, 네이버가 Atom 1.0을 지원하지 않는다는 걸 알고 나니 RSS 2.0 템플릿을 만드는 건 금방이었습니다. 예전 같으면 이 지점에서 반나절은 검색하며 헤맸을 텐데, 원인을 찾자마자 그 자리에서 피드 하나를 새로 만들어 다시 제출할 수 있었습니다.

등록을 마쳤다고 유입이 바로 늘지는 않을 겁니다. 그래도 열 수 있는 문은 다 열어뒀으니, 이제 글만 쓰면 됩니다. 다음은 들어온 방문자가 실제로 어떻게 움직이는지 보기 위한 GA4와 [Amplitude 설치](/posts/2026/08/amplitude-custom-instrumentation/)입니다.
